# AURA

**A verifiable creative-agent marketplace, proven live on 0G.**

A creative **agent** is an **iNFT** (ERC-7857-style). It owns a public identity, a private style-DNA "brain" sealed (encrypted) on 0G Storage, and the TEE attestation of the model it runs on. When that agent makes art, it generates on **0G Compute inside a TEE**, so every output carries **unforgeable provenance**: which agent, which model, proven in hardware. Because authorship is provable on-chain, the agent's owner earns an **enforced, transferable royalty on every output sale, forever**. Sell the agent and its entire future royalty stream goes with it.

This repo is **one end-to-end loop, executed for real on the 0G Galileo testnet**. No mocks. Every step below is a live `0G Compute` call, a real `0G Storage` upload, or a confirmed `0G Chain` transaction. **All 28 transactions resolve on the public explorer.** The machine-readable proof of the run that already happened is [`demo/proof.json`](./demo/proof.json); the script that produced it is [`demo/run-aura.ts`](./demo/run-aura.ts).

> **Network:** 0G Galileo testnet · chainId **16602** · explorer https://chainscan-galileo.0g.ai
> **Run it yourself:** `pnpm install` → put a funded testnet key in `.env` → `pnpm demo`

## The problem

Two things have never worked together for AI-generated art:

1. **Provenance is unprovable.** On every NFT marketplace today, "who made this" is just whatever the uploader typed. Anyone can mint anyone's art. There is no cryptographic proof that a specific model produced a specific image.
2. **Royalties are a polite suggestion.** EIP-2981 advertises a royalty, but enforcement is opt-in. Most marketplaces dropped it; creators collect little to nothing on secondary sales. And the royalty is bolted to a token, not to the *creator's identity*, so it cannot be sold or transferred as an asset in its own right.

| | Provenance (who/what made it) | Royalty enforcement | Royalty transfers with the creator |
|---|---|---|---|
| OpenSea + generic NFT marketplaces | "trust the uploader", unprovable | optional, mostly ignored on secondary | no |
| Royal / Sound.xyz (creator-royalty NFTs) | off-chain trust in the platform | platform-dependent | no |
| **AURA on 0G** | **TEE-proven: which agent, which model, in hardware** | **paid inside `buy()`, before the seller, unbypassable in-platform** | **yes: sell the agent iNFT and the whole royalty stream goes with it** |

The reason nobody shipped the right-hand column is that it needs **verifiable compute** (to prove an output really came from a specific model) sitting next to **permanent storage** and an **EVM chain that resolves royalty dynamically to the agent's current owner**. 0G is the only stack where all three are native, so the whole loop is buildable in one place.

## The thesis: why this is only possible on 0G

Take away 0G's TEE compute and the provenance is spoofable, so a "verified creator royalty" means nothing. Put it on a normal NFT marketplace and the royalty is unenforced. AURA makes both **provable** and **enforced**, and it does so because **all four 0G primitives are load-bearing**, not decorative:

| Primitive | What it does in AURA | Remove it and... |
|---|---|---|
| **0G Compute** | TEE-verified image generation (`qwen/qwen-image-edit-2511`, TeeML / dstack). `processResponse()` returns a hardware-signed pass: *this output was generated by this model, in a TEE.* | provenance is just a claim; anyone can fake authorship. |
| **0G Storage** | Holds the artwork, the signed provenance record, **and** the agent's encrypted style-DNA brain. Every upload's local merkle root is verified equal to the on-chain root. | the art and the proof live on a server someone can edit or delete. |
| **0G Chain (EVM)** | The iNFT, the on-chain provenance (image root + provenance hash + TEE attestation baked into each OutputNFT), and the enforced royalty split inside the Marketplace. | no enforced royalty, no on-chain provenance binding. |
| **iNFT (ERC-7857-style)** | The agent *itself* is a transferable token. Royalty resolves dynamically to `AgentRegistry.ownerOf(creatorAgentId)`, so ownership of the agent *is* ownership of its royalty stream. | the royalty cannot follow a creator or be sold as an asset. |

The economic primitive that no prior marketplace has, **a royalty that is provably earned by a verified creator and transferable with that creator**, falls out of putting these four together. That is the whole bet.

## Architecture

```
                          ┌──────────────────────────────────────────────┐
                          │                    AURA                       │
                          └──────────────────────────────────────────────┘

   AGENT (iNFT)                 GENERATE                  STORE                MINT + PROVENANCE
   AgentRegistry.sol            0G Compute (TEE)          0G Storage           OutputNFT.sol (721+2981)
   ┌───────────────┐            ┌──────────────┐          ┌────────────┐       ┌──────────────────────┐
   │ public identity│  owns ──▶ │ qwen-image-  │  bytes ▶ │ image root │  ───▶ │ creatorAgentId        │
   │ style fingerprint         │ edit-2511    │          │ provenance │       │ imageRoot (0G Storage)│
   │ encBrainRoot ───┼─sealed──▶│ TeeML/dstack │          │ enc. brain │       │ provenanceHash        │
   │ modelAttestation│          │ processResp= │          └────────────┘       │ teeAttestation        │
   │ royaltyBps      │          │   TRUE  ✓    │            merkle == on-chain  └──────────┬───────────┘
   └───────┬─────────┘          └──────────────┘            root  ✓                       │
           │                                                                              ▼
           │ ownerOf(creatorAgentId)  ◀─────── royaltyInfo() resolves dynamically ──── Marketplace.sol
           │                                                                          list / buy()
           ▼                                                                              │
   royalty receiver = the agent's CURRENT owner                                           ▼
   (transfer the agent → the SAME artwork's royalty follows it)             enforced split, paid inside
                                                                            buy() BEFORE the seller:
                                                                            royalty → agent owner
                                                                            platform fee → platform
                                                                            proceeds → seller
```

Three contracts, one off-chain runner:

- **`contracts/src/AgentRegistry.sol`** - the iNFT. ERC-721 carrying the agent's public identity, style fingerprint, encrypted-brain pointer, model attestation, and royalty bps.
- **`contracts/src/OutputNFT.sol`** - ERC-721 + EIP-2981. Each minted output bakes in `creatorAgentId`, the 0G Storage image root, the provenance hash, and the TEE attestation. `royaltyInfo()` resolves to the agent's *current* owner.
- **`contracts/src/Marketplace.sol`** - enforced royalty split. `buy()` pays the agent-owner royalty and platform fee *before* the seller and *before* the NFT transfers.
- **`demo/run-aura.ts`** - the phased, resumable runner that executes the whole loop live and journals every step to `demo/proof.json`.

## The loop (what `pnpm demo` does, live)

```
register agent (iNFT)  →  generate on 0G Compute (TEE)  →  store on 0G Storage
   →  mint OutputNFT (provenance + storage root + attestation baked in)
   →  list + sell on the Marketplace  →  enforced royalty routes to the agent's
      CURRENT owner  →  drop a real PFP collection (1 character, N trait variations)
```

The runner is **phased, idempotent, and resumable**: it journals each step to `demo/proof.json`, skips work already proven, and never double-mints or double-spends. That resumability is real, not aspirational: this very run was killed twice mid-collection and resumed from its journal with zero rework (see the repeated banners and `already minted` lines in [`demo/run-highlights.log`](./demo/run-highlights.log)).

```
pnpm demo                 # full loop; resumes from demo/proof.json
pnpm demo --regen         # ignore the journal, run every phase fresh on-chain
pnpm demo --only=royalty  # run one phase: agent | hero | royalty | collection
```

## Run it yourself

**Prerequisites:** Node 22+, [pnpm](https://pnpm.io), and a funded Galileo testnet wallet (faucet: https://faucet.0g.ai, ~0.5 0G per claim; the full run spends ~0.1 0G).

```bash
pnpm install

# put a funded testnet private key in .env (this file is gitignored):
#   PRIVATE_KEY=0x...
#   ADDRESS=0x...
cp .env.example .env   # then edit

pnpm demo              # runs the full loop live; resumes from demo/proof.json if re-run
```

The contracts are already deployed at the addresses above (live on Galileo), so `pnpm demo` exercises the deployed system. To redeploy from scratch, see [`contracts/README.md`](./contracts/README.md) (Foundry; Galileo needs `--legacy --gas-price 5000000000`).

**Smoke tests** for each primitive in isolation live in `src/` (`pnpm wallet`, `pnpm balance`, `pnpm compute`, `pnpm storage`, `pnpm e2e`) and are documented in [`report.md`](./report.md). The contract thesis is proven locally by `contracts/test/Smoke.t.sol` (5/5 passing, including `test_RoyaltyFollowsAgentOnTransfer`).
